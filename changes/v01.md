# v0.1 — Multi-Modal Evaluation Engine

## Overview

Added a multi-signal evaluation pipeline that aggregates AI, embedding-based semantic matching, and human mentor feedback to produce fair, explainable assessments with progressive scoring.

- **AI + Embedding** signals produce a numerical score (weighted average)
- **Human mentor** provides qualitative feedback only (no scores)
- Scores update progressively: `pending` -> `in_progress` -> `provisional` -> `final`
- Trust weights calibrate dynamically based on inter-signal agreement

## New Files

### Evaluators (`src/api/evaluators/`)

| File | Description |
|------|-------------|
| `__init__.py` | `BaseEvaluator` abstract class and `EvaluationSignal` dataclass — common interface for all evaluators |
| `ai_evaluator.py` | Extracts evaluation signals from existing LLM output. Supports subjective (scorecard-based), objective (correct/incorrect), and assignment (key area scores) question types. Does NOT make separate LLM calls — reuses the already-produced AI response |
| `embedding_evaluator.py` | Scores submissions by cosine similarity against reference answers using OpenAI `text-embedding-3-small`. Pure Python cosine similarity (no numpy). Confidence scales with number of reference answers |
| `human_evaluator.py` | Creates feedback-only signals from mentor reviews. No numerical scores — mentors provide per-criterion textual comments and overall feedback |
| `aggregator.py` | Weighted average aggregation of automated signals (AI + embedding). Generates explainable JSON breakdowns. Trust calibration based on inter-signal agreement |
| `pipeline.py` | Orchestrates the full evaluation pipeline as an async fire-and-forget task. Called via `asyncio.create_task()` after AI response completes — does not block streaming |

| Column | Type | Description |

### `evaluator_trust` table

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PK | Auto-increment |
| org_id | INTEGER FK | Organization |
| evaluator_type | TEXT | `ai` / `embedding` |
| trust_weight | REAL | Current weight (defaults: ai=0.65, embedding=0.35) |

## Scoring Formula

```
final_score = (SUM(normalized_score_i * weight_i * confidence_i) / SUM(weight_i * confidence_i)) * max_score
```

Only automated signals (AI, embedding) contribute. Human feedback is attached to the explanation but does not affect the numerical score.

### Trust Calibration

After each evaluation with both AI and embedding signals:

```
agreement = 1 - |ai_normalized - embedding_normalized|
new_weight = max(0.10, base_weight * (total_agreements / total_evaluations))
```

Floor of 0.10 prevents any evaluator from being zeroed out.

## Architecture Flow

```
Student submits answer
    |
    v
AI streams feedback to student (unchanged behavior)
    |
    v (async, non-blocking)
Evaluation Pipeline fires:
    +-- AI signal extracted from LLM output
    +-- Embedding signal via cosine similarity to reference answers
    +-- Trust weights calibrated based on signal agreement
    +-- Provisional score computed
    |
    v (later, when mentor reviews)
Mentor submits qualitative feedback
    +-- Status: provisional -> final
    +-- Score unchanged, explanation enriched with human feedback
```
